# 报表审计 (Statement Auditor)

## 概述

Statement Auditor 是基金 LP 报表分发前的**最后一道质检关卡**。负责将 statement-reader 提取的 LP 报表与 NAV 数据包进行逐字段交叉比对，发现差异、诊断根因、出具签批报告，确保每份分发给有限合伙人（LP）的报表准确无误。

**核心原则：** LP 报表**不可信**——视其为待验证数据，必须以 NAV 数据包为权威基准进行逐字段审计。任何差异未澄清前，不得分发。

## 触发条件

- 月度/季度 LP 报表生成完毕，准备分发前
- NAV 数据包已由基金会计完成更新
- 审计过程中发现报表历史差异需要追溯
- 新基金首期报表或重大资产变更后的首次审计
- 系统切换/升级后的平行验证

## 产出

### 1️⃣ 勾稽表 (Reconciliation Matrix)

每个 LP 报表字段与 NAV 数据包的逐字段对比结果：

| 字段 | 报表值 | NAV参考值 | 差异 | 匹配状态 | 备注 |
|------|--------|-----------|------|---------|------|
| 基金净值(NAV) | ¥1,234,567 | ¥1,234,567 | ¥0 | ✅ 匹配 | — |
| LP份额 | 100,000.00 | 100,000.00 | 0.00 | ✅ 匹配 | — |
| 单位净值 | 12.34567 | 12.34567 | 0.00000 | ✅ 匹配 | — |
| 累计收益 | ¥246,913 | ¥247,000 | -¥87 | ❌ 不匹配 | 差异率0.04% |
| 实缴资本 | ¥987,654 | ¥987,654 | ¥0 | ✅ 匹配 | — |
| ... | ... | ... | ... | ... | ... |

**匹配状态分类：**
- ✅ **匹配** — 差额≤容忍阈值（默认权益类0.01%，现金类0.001%）
- ⚠️ **超阈值** — 差额>容忍阈值但≤警戒线（需标记）  
- ❌ **不匹配** — 差额>警戒线（必须出具异常）

### 2️⃣ 异常清单 (Exception List)

每条差异的详细信息及疑似原因：

| # | 字段 | 报表值 | NAV值 | 差异 | 差异率 | 疑似原因 | 风险等级 |
|---|------|--------|-------|------|--------|---------|---------|
| 1 | 累计收益 | ¥246,913 | ¥247,000 | -¥87 | 0.04% | 未含当日分红调整 | 🟡 低 |
| 2 | 管理费计提 | ¥12,345 | ¥12,000 | ¥345 | 2.88% | 费率基准日差异（月末 vs 月初） | 🟠 中 |
| 3 | 托管费 | ¥2,469 | ¥2,000 | ¥469 | 23.45% | 托管费率变更未同步至报表系统 | 🔴 高 |

**疑似原因分类：**
| 分类 | 说明 | 处理方式 |
|------|------|---------|
| 分红/分配调整 | 报表未含期后分红或分配 | 与NAV对齐日期 |
| 费率基准差 | 管理费/托管费使用不同基准日 | 统一费率基准 |
| 汇率差异 | 外币资产使用的汇率口径不同 | 确认汇率来源统一 |
| 时间差 | NAV截止日后发生的交易未反映 | 确认截止日是否一致 |
| 计算口径 | 公式/取整规则不同 | 确认计算规范 |
| 数据错误 | 报表或NAV数据输入错误 | 追溯原始凭证 |
| 未明 | 无法定位根因 | 标记人工复核 |

## 工作流

### Step 1: 读取报表（Read Statements）

调用 statement-reader 提取 LP 报表内容。

```
调用工具：statement-reader / document-parser
输入：LP 报表文件（PDF / Excel / CSV）
输出：结构化报表数据（JSON / DataFrame）
```

**⚠️ 安全规则：**
- 报表数据**标记为"不可信"**，存储时不写入正式账套
- 仅在审计隔离区（sandbox）内使用
- 所有报表字段必须与 NAV 数据包交叉验证

**数据源适配示例：**
```python
# 使用 OCR 解析 PDF 报表
from ocr-and-documents import extract_pdf
lp_statement = extract_pdf("LP_Statement_Q1_2024.pdf")

# 或使用 Excel 读取
import pandas as pd
lp_statement = pd.read_excel("LP_Statement_Q1_2024.xlsx", sheet_name="Statement")
```

### Step 2: 对账（Reconcile）

逐字段与 NAV 数据包对比，使用 Tushare / 内部系统获取 NAV 参考值。

```python
# 伪代码：逐字段对账逻辑
def reconcile_field(field_name, statement_value, nav_value, threshold=0.0001):
    if field_name in ('NAV', 'unit_nav', 'total_nav', 'equity'):
        # 数值型字段：绝对值+相对值双重校验
        abs_diff = abs(statement_value - nav_value)
        rel_diff = abs_diff / max(abs(nav_value), 1)
        status = "MATCH" if rel_diff <= threshold else "MISMATCH"
        return {"field": field_name, "abs_diff": abs_diff, 
                "rel_diff": rel_diff, "status": status}
    elif field_name in ('lp_share', 'ownership_pct', 'capital_call'):
        # 份额/比例型字段：精确匹配
        is_match = statement_value == nav_value
        return {"field": field_name, "diff": 0 if is_match else abs_diff, 
                "status": "MATCH" if is_match else "MISMATCH"}
    elif field_name in ('currency', 'report_date', 'fund_name'):
        # 文本型字段：字符串完全匹配
        is_match = str(statement_value).strip() == str(nav_value).strip()
        return {"field": field_name, "status": "MATCH" if is_match else "MISMATCH"}
```

**对账顺序（按风险从高到低）：**

1. **NAV 核心字段：** 基金净值、单位净值、累计净值
2. **LP 权益字段：** LP 份额、实缴资本、分配
3. **收益字段：** 累计收益、未实现损益、已实现损益
4. **费用字段：** 管理费、托管费、业绩报酬
5. **元数据字段：** 基金名称、报告期、货币单位

**Tushare MCP 数据获取（NAV 参考）：**
```python
# 获取基金净值参考
mcp_tushare_fund_nav(ts_code='XXX.SH', start_date='...', end_date='...')

# 获取持仓市值参考
mcp_tushare_daily_basic(ts_code='600XXX.SH', trade_date='YYYYMMDD')

# 获取分红数据
mcp_tushare_dividend(ts_code='600XXX.SH', ex_date='...')

# 获取汇率参考
mcp_tushare_fx_daily(ts_code='USDCNY', trade_date='YYYYMMDD')
```

### Step 3: 标记异常（Flag Exceptions）

提交 flagger 格式化异常清单和签批表。

```markdown
# Flagger 格式化指令

## 异常清单格式
每条异常需包含：
1. 字段名称及路径（报表中的具体位置）
2. 报表值（原始值，不修正）
3. NAV参考值（带数据源和时间戳）
4. 差异金额和差异率
5. 疑似原因分类（见上述分类表）
6. 支持证据（相关交易流水/公告/截图）
7. 风险等级（高/中/低）

## 签批表格式
- 自动计算统计概览（匹配/不匹配数量）
- 根据风险等级自动判定通过条件：
  - 0 个 🔴 高风险 → 有条件通过或通过
  - ≥1 个 🔴 高风险 → 暂缓分发
- 预填各责任方签批栏目
```

### Step 4: 独立复核（Critic Review）

启用 Critic 角色对审计结果进行复核：

1. 核实勾稽表计算逻辑（所有数值交叉验算）
2. 检查异常分类是否合理（疑似原因是否站得住脚）
3. 确认高风险差异是否另有遗漏
4. 验证签批表建议是否合理

**复核清单：**
- [ ] 所有数值计算经独立复核
- [ ] 异常清单的每种分类有足够证据支持
- [ ] 暂缓/通过建议与风险等级一致
- [ ] 报表数据未与正式账套混合
- [ ] NAV 数据包来源标注清晰、时效性有效

## 安全规则

### 报表不可信原则

```
┌──────────────────────────────────────────┐
│           安全隔离区 (Sandbox)             │
│                                          │
│  LP报表 (不可信)  ───→  statement-reader   │
│       │                                    │
│       ▼                                    │
│  结构化解析   ──→  字段提取                   │
│       │                                    │
│       ▼                                    │
│  NAV数据包 (权威)  ──→  逐字段对比            │
│       │                                    │
│       ▼                                    │
│  ▸ 勾稽表 (仅审计区)                        │
│  ▸ 异常清单 (仅审计区)                      │
│  ▸ 签批表 (仅审计区)                        │
│                                          │
│  签批通过 ──→ 报表正式分发                   │
│  签批暂缓 ──→ 退回修正                      │
└──────────────────────────────────────────┘
```

**具体规则：**

1. **不直接分发：** 任何 LP 报表未经过审计流程不得直接分发给 LP
2. **数据隔离：** 报表数据存储在独立的审计目录，不与正式账套交叉
3. **不自动修正：** 审计报告指出差异，但不自动修改报表或 NAV 数据
4. **来源标注：** 勾稽表中每个 NAV 参考值必须标注数据源和时间戳
5. **版本控制：** 每次审计生成唯一版本号，便于追溯
6. **访问控制：** 审计报告仅限基金会计、合规、审计主管三级查阅

## 典型场景

### 场景 1：月度 LP 报表分发前审计

1. 基金会计完成本月 NAV 计算 → 导出 NAV 数据包
2. 报表团队生成 LP 报表（PDF/Excel）
3. **Statement Auditor 介入：**
   - 读取 LP 报表，提取所有字段
   - 与 NAV 数据包逐字段比对
   - 发现管理费计提差异 ¥345 → 标记为"费率基准差"，中风险
   - 发现累计收益差异 -¥87 → 标记为"分红调整"，低风险
4. 输出勾稽表 + 异常清单 + 签批表
5. 基金会计确认差异原因，修正报表后重新提交
6. 二次审计通过 → 签批 → 分发

### 场景 2：季度报告审计（含业绩报酬计算）

1. 提取季度 LP 报表（含 realised/unrealised P&L 拆分）
2. NAV 数据包包含：
   - 每个持仓的未实现损益计算表
   - 已实现损益交易流水
   - 业绩报酬计算明细
3. 审计重点：
   - 已实现损益是否与交易流水一致
   - 未实现损益是否按最新市价计算
   - 业绩报酬 High Water Mark 计算是否正确
4. 输出专项审计报告

## 常见陷阱

1. **截止日不对齐：** NAV 计算截止日与报表截止日可能差 1-2 个工作日。**必须统一以资产估值日为准。**
2. **四舍五入误差：** 不同系统的小数位处理不同（NAV 6 位 vs 报表 2 位）。**设置合理的容忍阈值。**
3. **分红未还原：** 累计收益字段容易忽略期后分红。**需要与 dividend 数据交叉验证。**
4. **汇率陈旧：** 报表使用的汇率可能是历史汇率而非最新结算汇率。**确认汇率基准日。**
5. **份额稀释：** 期内有新增认购或部分赎回时，LP 份额和占比需同步更新。**核对资本变动流水。**
6. **费用基数不一致：** 管理费按月初 NAV 还是月末 NAV 计提？**与基金合同条款核对。**
7. **业绩报酬 High Water Mark：** 不同基金可能有不同的 HWM 机制（hard hurdle / soft hurdle / catch-up）。**需查阅具体基金合同。**
8. **NAV 数据包本身也有错误：** NAV 数据包以权威基准对待，但仍可能在极端情况下存在错误。**如差异持续存在，应启动 NAV 复核流程。**
9. **MCP 数据延迟：** Tushare 的基金净值等数据可能 T+1 更新。**审计时需注意数据时效性。**
10. **文本不一致：** "单位净值" vs "每份净值" 等用词差异。**建议建立字段映射表提前统一。**
11. **汇率口径不一致：** 中间价 vs 买入价 vs 卖出价。**应在标准汇率表上统一。**
