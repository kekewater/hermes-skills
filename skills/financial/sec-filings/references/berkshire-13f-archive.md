## 核心发现：13F `<value>` 单位变化

SEC 在 **2023 年** 悄无声息地变更了 13F XML 中 `<value>` 的数值单位，**这是最重要的数据陷阱**：

- **2013~2022年**：`<value>` 单位为 **千美元 (thousands of USD)**
  - Apple 2017-02-14: `6,643,394` → 实际 $66.4亿（非$66.4M）
  - Wells Fargo 2013-08-15: `19,113,442` → 实际 $191.1亿
  
- **2023年起**：`<value>` 单位为 **实际美元 (US dollars)**
  - Apple 2023-02-14: `116,305,043,218` → $1,163亿
  - 直接对比前后相差约 **1,000倍**

**验证方法**：`value / shares ≈ 报告期股价`，否则需要归一化。

## 采集脚本框架

见 `scripts/fetch_13f.py`，核心逻辑：

1. `edgar.configure_http(timeout=120.0)` — 大文件超时保护
2. 检查点续传（`checkpoint.json`）— 分批处理209份文件
3. `re.findall(r'<infoTable>.*?</infoTable>', txt, re.DOTALL)` — 解析XML持仓
4. 单位归一化：`if filing_date < '2023' and value < 1e8: value *= 1000`
5. `time.sleep(2.5)` — 保守限频，避免429

## 注意事项

- 纯文本格式（1999~2012年）的150份文件需另写解析器
- XML中的发行商名称带HTML转义（`&amp;`→`&`）
- 部分报告期含"修正"（amendment），标注为同一日期多份文件
- 2023年后格式变更后，数字精度更高（原千美元整→美元精确值）
